# M2 dogfooding 기록

> 시작: 2026-08-04 | 브랜치 feature/m2-telemetry

## 무엇을 만들었나

**계측 계층** — 훅이 이벤트를 `~/.mind-reader/<프로젝트>/events.jsonl`에 남기고, `npm run stats`가 집계한다.

| 이벤트 | 시점 |
|---|---|
| `cycle_start` | 실질 요청으로 의도 파악 사이클이 시작될 때 |
| `spec_presented` | 명세가 제시될 때 (내용이 바뀐 경우만 버전 증가) |
| `approved` | 승인 시 — 질문 수, 명세 버전 수 함께 기록 |
| `gate_deny` | 게이트가 도구를 차단할 때 (도구명) |
| `stop_block` | 종료가 차단될 때 |

**산출 지표**: 질문 발생률, 평균 질문 수, 명세 수정률(핵심 지표 — 0%에 가까우면 확인 단계가 형식적), 미완료율, 차단 분포.

## 설치 첫날 발견한 결함 4건

전역 설치 직후 **도구가 개발자 자신의 작업을 차단**했고, 그 과정에서 심각한 결함이 연쇄적으로 드러났다.

### 1. idle 데드락 (critical)
게이트가 `approved`가 아니면 전부 차단하도록 되어 있었다. 사이클이 시작되지 않은 `idle` 상태에서는 **승인할 명세 자체가 존재하지 않는데** 파일 수정도 명령 실행도 막히므로, 도구 안에 빠져나올 경로가 없었다.
→ `probing`/`spec_pending`일 때만 차단하도록 수정. 사이클이 없으면 막을 이유가 없다.

### 2. uninstall이 자기 훅을 못 찾음 (critical)
M1 코드 리뷰에서 "경로 기반 식별은 취약하다"는 지적을 받아 `_mindReader` 마커 필드로 바꿨는데, **Claude Code가 settings.json을 정규화하면서 알 수 없는 필드를 제거**한다. 결과적으로 훅은 살아 있는데 uninstall은 0건을 찾아 "제거 완료"를 출력했다 — 제거 불가 상태.
→ 설치 시 `~/.mind-reader/install.json`에 명령 문자열을 기록하고, 매니페스트 → 실행 경로 → 마커 순으로 식별. 정규화와 무관하게 동작한다.

### 3. 프로젝트 단위 예외 부재
탈출구가 전역 비활성화(`MIND_READER_OFF=1`)와 완전 제거뿐이라, mind-reader 자체를 개발하려면 dogfooding을 포기해야 했다.
→ `.mind-reader-off` 파일(상위 경로까지 탐색) 추가. 이 저장소에 적용.

### 4. 셀프 테스트 무력화
`.mind-reader-off`를 저장소에 두자 `install.sh`의 셀프 테스트가 조용히 건너뛰어졌다. 설치 검증이 사라지면 M1에서 기록한 "훅 기동 실패 시 게이트가 열린다"는 리스크를 감지할 수 없다.
→ 임시 디렉토리에서 검증하고, 실패 시 `exit 1`.

### 부수 발견
- 테스트가 실사용 지표를 오염시켰다(임시 프로젝트 52곳이 집계에 섞임) → 테스트에서 `HOME` 격리
- Stop 훅의 트랜스크립트 레이스가 실제로 발생 — 명세를 제시했는데 감지되지 않아 종료가 한 번 차단됐다. M1에서 알려진 한계로 기록해둔 것이 실사용에서 재현됨

## 검증

- 테스트 103건 통과 (신규 16건: idle 통과 5, 프로젝트 예외 5, 제거 왕복 6)
- 제거 왕복 실측: 마커가 제거된 상태를 재현하고 uninstall이 실제로 3건을 제거하는지 확인
- 새 세션 스모크: 모호한 요청에 질문 발동, 파일 생성 0건
- 설치 후 훅 3종 등록 확인, 기존 사용자 훅 11건 보존

## 관찰 대상 (지속)

- **명세 수정률** — 이 도구의 성패를 가르는 단일 지표. 0%에 수렴하면 확인 단계가 통과 도장이 된 것
- 질문 발생률이 과하면 발산 측정 게이트를 조이고, 낮으면 완화
- 게이트 차단 분포 — 정당한 조사가 과차단되는지
- Stop 레이스로 인한 불필요한 종료 차단 빈도
