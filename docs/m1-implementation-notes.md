| 파일 | 역할 |
|---|---|
| `src/hooks/prompt-submit.ts` | 매 프롬프트 발화. 경량 필터 → 승인 판정 / 새 사이클 / 프로토콜 주입. **fail-open** |

| `src/filter.ts` | 통과/요청/승인/의문형 판정. NFC 정규화 |

| `install.sh` / `uninstall.sh` / `install/merge-settings.js` | 마커 기반 훅 병합·제거, 백업, 셀프테스트 |

## 상태머신

```
idle ──실질 요청(주입)──▶ probing ──[MR-SPEC] 제시──▶ spec_pending ──"승인"──▶ approved
                            │                                                    │
                            └─ 문답 답변은 재주입 없음          새 발화 ──────────┘ (새 사이클)
```
- 상태는 `~/.mind-reader/<프로젝트해시>/<세션해시>.json` — **프로젝트 밖**에 둬서 게이트 대상(Bash)이 스스로 승인 상태를 쓰는 권한 상승을 차단
- 승인은 **직전 턴에 실제로 제시된 명세**에만 적용 (수정 요청 후 후속 질문에 "ok" 한 마디로 구명세가 승인되는 것 방지)

## 검증

**유닛 68건 통과** (`npm test`, 컴파일된 dist 훅을 실제 stdin/stdout로 구동)
- C1 우회 명령 15종 전부 차단 / 정상 읽기 명령 10종 전부 통과
- 부정 표현 5종·일상 답변 6종 비승인, `승인`만 승인
- default deny: 쓰기·MCP·미래 도구 6종 차단, 읽기 6종 통과
- 설치: 3회 재설치 무중복, 경로 무관 제거, 사용자 훅·다른 설정 보존, 배열 JSON 거부

**E2E (헤드리스 `claude -p --resume`, haiku) 전 구간 통과**
1. "설정 파일 하나 만들어줘" → 선택지 질문(권장안 표시), 파일 미생성
2. "2번 백엔드 API, Node.js로" → [MR-SPEC] 명세 (✓답변/~가정/하지 않을 것/변경될 것/검증)
3. **반증**: "ok" → 승인 안 됨, 파일 미생성 / "아직 승인 안 할래" → 승인 안 됨, 파일 미생성
4. "승인" → 게이트 해제, tsconfig.json 생성(명세대로), 명세 아카이브 저장

## E2E에서 발견해 고친 버그 3건

1. **한국어 필터 컷** — "여기 정리 좀 해줘"(9자)가 단답으로 오분류 → 요청 동사 패턴 도입
2. **Stop 훅 트랜스크립트 레이스** — Stop 시점에 마지막 메시지 미기록 → 승인 판정을 prompt-submit에서 직접 확인하도록 이중화

## 알려진 한계 (M2 dogfooding 관찰 대상)

- **훅 프로세스 자체가 기동 실패하면(dist 없음, node 없음, 타임아웃) fail-closed가 성립하지 않음** — Claude Code가 non-blocking 오류로 처리. 운영(설치 셀프테스트)으로만 방어 가능
