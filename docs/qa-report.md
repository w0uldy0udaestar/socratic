## 검증한 것

### 견고성 (`test/robustness.js`)

- **비정상 stdin** — 빈 입력, 깨진 JSON, 배열, null, 문자열, 빈 객체 → 훅 3종 모두 크래시 없음
- **손상된 상태 파일** — 깨진 JSON, 빈 파일, 유효하지 않은 phase 값, `"approved "`(공백 위장) → 전부 idle로 안전하게 처리
- **트랜스크립트 이상** — 경로 없음, 존재하지 않는 파일, 빈 파일, 깨진 줄 혼재(명세는 여전히 인식), **1만 줄 대용량 44ms**
- **극단적 입력** — 100KB 프롬프트, NFD 한글, 이모지, 중국어, 제어문자, 다중 개행

- **동시성** — 20개 프로세스 동시 상태 쓰기 후 파일 유효(원자적 교체 확인), 임시 파일 잔여 없음
- **stats** — 깨진 줄 섞인 로그도 집계, 존재하지 않는 경로에도 크래시 없음

### 서브에이전트 게이트 상속 — 핵심 미검증 항목 해소

`Task`/`Agent`를 항상 허용 목록에 둔 것이 우회 구멍인지 확인하기 위해, 프로젝트 스코프 설정에 관측용 훅을 등록하고 서브에이전트를 띄웠다.

```
{"sid":"3ba00b55-...","tool":"ToolSearch"}   ← 부모
{"sid":"3ba00b55-...","tool":"Agent"}        ← 부모가 서브에이전트 기동
{"sid":"3ba00b55-...","tool":"Bash"}         ← 서브에이전트 자신의 호출
```

**결론**: 서브에이전트 내부 도구 호출도 `PreToolUse`를 거치며, **부모와 같은 `session_id`를 공유**한다. 상태 조회가 일치하므로 게이트가 그대로 적용된다. 서브에이전트를 띄워 우회하는 경로는 없다.

## QA 중 발견·수정한 결함

### 경로 정규화 불일치 (수정 완료)

macOS의 `/var` → `/private/var` 심볼릭 링크 때문에, 같은 프로젝트가 두 가지 경로 문자열로 전달되면 **상태 디렉토리가 갈라져 승인이 유실**될 수 있었다. E2E 중 상태 파일을 찾지 못하는 현상으로 드러났다.

→ `projectDir()`에서 `fs.realpathSync()`로 정규화. 두 형태가 같은 상태 디렉토리로 수렴하는 것을 확인했다. 테스트 헬퍼 5개 파일도 같은 기준으로 맞췄다.

## 남은 관찰 (설계 판단 필요)

### 1. 사소한 요청에도 명세·승인을 강요한다 — 우선순위 높음

`"log.txt에서 오타 두 개를 고쳐줘: aplication → application, loded → loaded"` 처럼 **해석의 여지가 전혀 없는 요청**에도 사이클이 시작되고, 쓰기가 두 번 차단되고, 명세 제시 후 승인을 기다렸다.

계측상 `questions: 0` — 발산 측정은 정상 작동해서 질문은 하지 않았다. 문제는 그 다음이다. **질문할 게 없다고 판단했는데도 명세+승인 왕복이 강제된다.** D2(명세 승인 후 실행)를 모든 요청에 적용한 결과이며, 오타 수정에 왕복 2회는 비용이 크다.

선택지: ① 현행 유지(모든 실행에 승인) ② 발산이 0이고 변경 범위가 작으면 명세를 제시하되 승인 없이 진행 ③ 사용자가 임계값을 설정. **M2 지표(미완료율)로 판단하는 것이 적절하다** — 미완료율이 높으면 사용자가 승인까지 안 가고 이탈한다는 뜻이다.

### 2. Stop 훅이 한 턴에 3회까지 차단됨

모호한 요청 E2E에서 `stop_block` n=1,2,3이 연속으로 관측됐고, 그 후 명세가 제시됐다. 안전 밸브(MAX_BLOCKS=3)가 매번 소진되면 Stop 게이트는 사실상 3회 넛지로 동작한다. 모델이 프로토콜을 늦게 따르는 것인지, 트랜스크립트 레이스로 인한 오탐인지 구분이 필요하다.

### 3. HOME 쓰기 불가 시 게이트가 조용히 열린다

상태를 읽지 못하면 사이클 진행 여부를 알 수 없어 idle로 간주해 통과시킨다. 같은 조건에서 주입 훅도 실패하므로 도구 전체가 no-op이 되어 일관되기는 하지만, **사용자에게 아무 신호가 없다.**

### 4. `.mind-reader-off` 탐색 깊이 12단계 한계

20단계 하위 디렉토리에서는 상위의 예외 파일을 인식하지 못한다. 실사용에서 흔치는 않으나 모노레포에서 가능하다. git 루트까지 탐색하는 방식이 대안이다.
